# 픽업메이트 ETA·도착 알림·탑승자 위치 공유 설계

작성일: 2026-11-11 · 대상 저장소: `pickup-mate-lab/Pickup`(차량 앱), `pickup-mate-lab/pickup-passenger`(탑승자 앱·Go 서버)

## 1. 목적

참가신청서의 핵심 기능 3)·4)·2) 중 현재 동작하지 않는 부분을 완성한다.

| 기능 | 현재 | 목표 |
|---|---|---|
| 차량 도착 예정시간(ETA) 전달 | 서버·탑승자 앱에 표시 코드가 있으나 차량 앱이 ETA를 보내지 않음 | 차량 내비게이션의 남은 시간을 탑승자에게 실시간 전달 |
| 도착 임박·출발 시점 알림 | 5분 전 푸시 로직이 있으나 ETA가 없어 발송되지 않음. 출발 시점은 버튼을 누른 순간 1회 계산 | 출발 시점·도착 임박·도착 알림을 자동 발송하고 화면에 실시간 표시 |
| 탑승자 위치 공유 | 앱이 잠시 비활성화(권한 팝업, 알림창)만 돼도 공유가 꺼져 첫 공유가 조용히 실패 | 앱을 보는 동안 안정적으로 공유하고, 운전자 화면에 거리와 갱신 시각 표시 |

## 2. 결정 사항

- **ETA 출처: Pleos NaviHelper `DestinationInfo.remainTime`.** `navi-data` 3.0.4 소스 KDoc에 "estimated remaining travel time ... (in seconds)", 타입 `Int`로 명시됨. 외부 경로 API(TMAP 자동차)는 사용하지 않는다.
- **ETA 안전장치.** 경로 시작 시 받은 `RouteStartInfo.duration`(초)과 첫 `remainTime`을 비교해, 3배 이상 차이가 나면 단위 불일치로 보고 해당 경로의 ETA를 보내지 않는다. 내비 목적지가 승차 지점과 다르면 ETA를 보내지 않는다. 60초 이상 갱신되지 않은 ETA는 `null`로 보낸다.
- **위치 공유 범위: 앱을 보는 동안만 공유(포그라운드).** 백그라운드 위치 권한은 쓰지 않는다. 앱이 `paused`(실제로 화면을 벗어남)일 때만 공유를 멈추고, 탑승자가 공유를 켜 둔 상태였다면 앱으로 돌아왔을 때 자동으로 다시 켠다.
- **알림 판단은 서버가 한다.** 차량 위치·ETA 갱신 시 서버가 조건을 확인하고, 각 알림을 승차 지점 revision마다 1회 발송한다. 푸시는 Firebase가 설정된 계정 모드에서만 발송되며, 데모 모드에서는 탑승자 앱 화면 안내와 진동으로 대신한다.

## 3. 알림 규칙 (서버)

입력값: `ETA`(초, 차량 위치가 60초 이내로 갱신된 경우에만 유효), `walkingSeconds`(탑승자가 도보 시간을 확인한 경우, 현재 revision 기준), 차량과 승차 지점 사이 거리 `d`.

| 알림 | 조건 | 문구 |
|---|---|---|
| 출발 시점 | `walkingSeconds` 있음 && `ETA - walkingSeconds - 120 <= 0` | "지금 출발하면 차량 도착에 맞춰 승차 지점에 도착해요." |
| 도착 임박 | `ETA <= 300` | "차량이 곧 도착해요. 픽업 위치를 확인해 주세요." (기존 문구 유지) |
| 도착 | `d <= 100m` | "차량이 승차 지점에 도착했어요." |

- 한 번의 갱신에서 여러 조건이 맞으면 가장 늦은 단계 하나만 보내고(도착 > 임박 > 출발), 앞 단계들도 발송한 것으로 표시한다.
- 승차 지점이 바뀌면(revision 증가) 모든 알림 상태와 도보 시간이 초기화된다.
- 푸시 본문에는 좌표·전화번호·메시지 내용을 넣지 않는다(기존 원칙 유지).

## 4. 서버 응답 변경 (탑승자·운전자 공통 `view`)

추가 필드:

- `walkingSeconds`: 현재 revision에 대해 저장된 도보 시간, 없으면 `null`
- `departureInSeconds`: `max(0, ETA - walkingSeconds - 120)`, 둘 중 하나라도 없으면 `null`
- `arrivalStage`: `"none" | "departure" | "approaching" | "arrived"`, 위 규칙을 현재 값으로 평가한 결과

변경:

- `etaSeconds`: 차량 위치가 60초 넘게 갱신되지 않았으면 `null`
- `walking-estimate` 호출 결과를 세션에 저장한다(응답 형식은 기존과 같음).

## 5. 화면 변경

- **차량 앱**: 탑승자 위치 줄을 "탑승자: 승차 지점까지 약 Nm · N초 전 갱신"으로 표시한다. ETA 줄은 기존 그대로 두고, 이제 실제 값이 표시된다.
- **탑승자 앱**: 상태 카드에 ETA, 출발 안내("약 N분 뒤 출발" 또는 "지금 출발하세요"), 도착 단계를 표시한다. 단계가 바뀌면 SnackBar와 진동으로 알린다. 도보 시간 안내에서 "(조회 시점 기준)" 문구를 빼고 서버 값을 실시간으로 반영한다.

## 6. 범위 밖

- 백그라운드 위치 공유, 탑승자 앱의 로컬 알림 라이브러리 추가
- 차량 내비게이션 지도 위에 탑승자 마커 표시(NaviHelper에 해당 API 없음)
- Python 데모 서버(`demo_server/`) 기능 확장. 차량 앱이 `etaSeconds: null`을 보내도 기존 코드가 이미 처리한다.
- 데모(레거시) 경로의 도보 시간 API. 기존처럼 계정 모드 + `TMAP_APP_KEY`에서만 제공한다.

## 7. 검증

- Go 서버: 알림 규칙, 1회 발송, revision 초기화, ETA 만료를 단위 테스트로 검증 (`go test ./...`)
- 탑승자 앱: `flutter analyze`, `flutter test`
- 차량 앱: `gradlew :app:assembleDebug` 빌드. `remainTime` 실측은 Pleos 에뮬레이터에서 `adb logcat -s PickupEta`로 확인한다(경로 시작 직후 `remainTime ≈ duration`이고 주행 중 줄어드는지 확인).
